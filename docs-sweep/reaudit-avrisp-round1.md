## Requested judgments

- **Windows procedure executable?** Yes, as a documented workaround. The set now gives a deterministic serial/ISP path, a retry-based USB binding path, an INF pre-stage path and a Linux path, and it says plainly that an unbound host cannot keep the five-second window alive. The remaining risk is the firmware limitation CO-1 (initial configuration shares the idle timer), not a missing instruction. A first-time USB bind is still timing-dependent; the docs no longer pretend otherwise.
- **`efuse` the extended byte?** Yes. `isp.md:57` says "low/high/extended".
- **Speed table no longer claims completeness?** Yes. The page says seven hardware steps are tabulated and the other 157 are an approximate ladder; the range row says "about 96 kHz down to about 51 Hz (approximate)" and the text says the exact rate is not tabulated.
- **AVR053 `0x05` exchange usable?** Yes. The page gives `05` / `05 00` / `05 80` / `05 C0`, says the reply never carries an OSCCAL value, says the target firmware does the calibration and stores its own result, and gives the `-O` / `--osccal` host path plus the AVR053 link.
- **ISP↔PDI/TPI switch one sequence?** Mostly. `command-model.md` §Changing target interface is a single five-row table with LEAVE, wait/re-enter, rewire and select-new-interface columns, and the path pages link to it. The PDI↔TPI rows are the one incomplete part: they do not state the target data destination or say to move `/CLK` off the old clock pin (finding 5).

## New problems

**N1 — [minor] The prerequisite check commands omit the entry step.**
`host-tools.md:12-13` gives `avrdude -c avrispmkII -P usb -p m328p -n` and `avrdude -c stk500v2 -P COM5 -p m328p -n` "with a target wired and powered", but the personality must first be entered with `0x08` (USB) or `0x09` (serial).  A fresh user who runs the check before entry gets "cannot find device", and the following text at `host-tools.md:18-22` then blames "the driver or the avrdude build" rather than the missing entry.  Add "after entering with `0x08`" / "after entering with `0x09`" to the two check rows, or make the check a two-step example.

**N2 — [minor] The prerequisites table does not list the Windows binding tool or the INF source.**
`host-tools.md:16` lists "the OS driver" but not Zadig, which §Windows USB first use requires ("Open Zadig…", `host-tools.md:115`).  The optional pre-stage path at `host-tools.md:124-127` says to add a "WinUSB/libusb INF for `03EB:2104`" but does not say where that INF comes from.  Add Zadig to the prerequisites row and say the INF is generated by Zadig (or link a template); otherwise the user has to guess at the two Windows-only tools.
